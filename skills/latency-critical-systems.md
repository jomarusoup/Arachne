# 저지연 시스템

실시간 동작·핫 패스·스트리밍 신선도·실행 속도가 중요한 시스템에서 사용한다.
HFT 유사 인프라를 포함하지만 엔지니어링 관점에만 집중한다.

## 지표 분리

모든 것을 "빠르다"로 뭉치지 않는다. 다음을 별도로 추적:

- p50, p95, p99 지연
- 처리량(throughput)
- 데이터 신선도(freshness age)
- 큐 깊이(queue depth)
- 캐시 히트율
- 외부 API 응답 시간
- 브라우저 렌더 시간
- 부하 하의 정확성
- 실패·재시도 동작

## 핫 패스 매핑

사용자/이벤트에서 최종 가시 상태까지 경로를 작성:

```text
소스 이벤트 → 외부 API → 수집 워커 → 큐 → 캐시 → 엣지 라우트
→ 클라이언트 스트림 → 브라우저 렌더 → 사용자 가시 상태
```

각 구간을 별도로 측정한다.

## 최적화 순서

1. 불필요한 왕복 제거
2. 안정적인 읽기를 신선도 메타데이터와 함께 캐시
3. 작은 호출·쓰기를 배치 처리
4. 데이터 또는 사용자에 더 가까운 곳으로 연산 이동
5. 핫 경로와 콜드 경로 분리
6. 큐가 무한 증가하기 전에 배압(backpressure) 적용
7. 신선도 또는 UX 개선이 명확할 때만 스트리밍 사용
8. 오래된 데이터·저하된 프로바이더·잘못된 캐시 상태에 카나리 추가

## 검증

배포된 서피스가 있으면 라이브 읽기 검증:

- HTTP 타이밍 및 응답 헤더
- 프로바이더 신선도 타임스탬프
- 큐 또는 작업 상태
- 엣지/캐시 상태
- 실제 UI 신선도를 위한 브라우저 검증
- 재시도 및 저하 모드 주변 로그

시장 데이터 또는 실행 인접 경로에서는 오더북 나이, VWAP 가정, 프로바이더 상태, 킬 스위치 동작도 확인한다.

## 가드레일

- 필수 검증을 생략해서 지연을 최적화하지 않는다
- 빠른 캐시 히트 뒤에 오래된 데이터를 숨기지 않는다
- 측정 없이 클라이언트 레이블로 밀리초 동작을 주장하지 않는다
- 명시적 승인 게이트 없이 라이브 주문·파괴적 마이그레이션·고객 영향 배포를 실행하지 않는다
- 로그와 벤치마크 산출물에서 비밀값과 개인 페이로드를 제외한다
