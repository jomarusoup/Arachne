# API 계약 — 계약 우선 설계

경계를 넘는 데이터는 구현보다 계약을 먼저 정한다.
계약은 경계마다 정본 하나만 두고, 나머지는 모두 정본에서 파생한다.
"맞게 동작한다"는 주장은 정본과 대조한 증거로만 인정한다.

이 하네스의 기본 구성은 C 서버(이식 목표 Rust)와 TypeScript 클라이언트(웹·Electron)다.
요청·응답은 REST/JSON으로, 대용량 스트림은 고정 레이아웃 바이너리로 주고받는다.

## 역할 경계

| 질문 | 스킬 |
|---|---|
| 경계를 어떻게 정하고, 바꾸고, 검증하나 | **이 스킬** |
| URL·상태 코드·페이지네이션을 어떻게 설계하나 | `api-design` |
| JSON 필드 하나를 어떤 표현으로 보내나 (int64·Decimal·시각·null) | `json-contracts` |
| 프레이밍·링버퍼·팬아웃을 어떻게 구현하나 | `stream-pipeline-patterns` |
| 손실 정책·시퀀스 갭·재동기화 원칙은 무엇인가 | `data-throughput-accelerator` |
| C 구조체를 Rust로 어떻게 옮기나 | `c-to-rust-migration` |

## 언제 사용하나

- 새 엔드포인트나 새 스트림 채널을 만들기 전
- 기존 응답 필드·메시지 레이아웃을 바꾸기 전
- 클라이언트와 서버를 다른 사람·다른 세션이 동시에 구현할 때
- "서버는 고쳤는데 클라이언트가 깨졌다"는 사고가 난 뒤

## 1. 경계마다 정본 하나

정본은 사람이 고치는 유일한 원본이다. 파생물은 정본에서 생성하거나 정본과 대조해 검증한다.

| 경계 | 정본 | 파생물 | 대조 수단 |
|---|---|---|---|
| REST 요청·응답 | `openapi.yaml` | TS 타입, 문서, 서버 라우트 표 | oasdiff, 스키마 기반 응답 검증 |
| 바이너리 스트림 | C 헤더 구조체 (`*_msg.h`) | 레이아웃 매니페스트, TS 디코더 상수, Rust `repr(C)` 구조체 | 매니페스트 diff, 공유 테스트 벡터 |
| 설정·파일 형식 | 스키마 파일 하나 | 로더 코드 | 샘플 파일 검증 |

- C 서버는 OpenAPI를 생성해 주는 프레임워크가 없다. 그래서 `openapi.yaml`을 손으로 쓰는 정본으로 두고 C 핸들러가 그것을 따른다.
- FastAPI처럼 코드에서 스키마를 생성하는 제공자는 생성된 스냅샷을 커밋하고, 그 스냅샷을 정본으로 다룬다(`json-contracts`).
- 정본 위치는 저장소 `AGENTS.md`의 "구조" 절에 한 줄로 적는다. 위치가 적혀 있지 않으면 정본이 없는 것이다.

## 2. 계약 우선 워크플로

여섯 단계를 순서대로 밟는다. 각 단계는 산출물을 남긴다. 산출물이 없으면 다음 단계로 가지 않는다.

| 단계 | 할 일 | 산출물 |
|---|---|---|
| ① 소비자·소유자 식별 | 이 경계를 읽는 쪽과 정본을 고칠 권한이 있는 쪽을 적는다 | 계약 문서 머리의 소비자·소유자 목록 |
| ② 소비자 작업 기술 | 소비자가 이 데이터로 무엇을 하는지 문장으로 적는다 | "화면 X는 키별 최신 가격을 1초 안에 보여 준다" 같은 작업 목록 |
| ③ 최소 유용 계약 | 작업에 필요한 필드만 정본에 적는다. 쓰일지 모르는 필드는 넣지 않는다 | `openapi.yaml` 또는 `*_msg.h` 변경 |
| ④ 소비자 타입 생성·파생 | 정본에서 소비자 타입을 생성한다. 생성이 불가능하면 손으로 옮기고 대조 테스트를 붙인다 | `schema.d.ts`, 디코더 상수 + 대조 테스트 |
| ⑤ 제공자 검증 | 실제 제공자 출력을 정본에 대조한다 | 스키마 검증 로그, C 테스트 통과, 테스트 벡터 |
| ⑥ 증거 비교 통합 | 양쪽이 같은 벡터·같은 스키마로 통과한 결과를 나란히 놓고 합친다 | PR 본문의 검증 명령과 출력 |

```bash
# ④ REST — 정본에서 TS 타입 생성
npx openapi-typescript openapi.yaml -o src/api/schema.d.ts

# ⑤ REST — 실행 중인 C 서버 응답을 정본에 대조 (schemathesis 4.x 기준, 3.x 는 --base-url)
schemathesis run openapi.yaml --url http://127.0.0.1:8080

# ④⑤ 스트림 — C 헤더에서 매니페스트·벡터 생성, C·TS 양쪽 디코더 검증
make -C src/contract test layout ts-test
```

- ②를 건너뛰면 ③이 커진다. 소비자 작업 없이 추가된 필드는 지울 수 없는 부채가 된다.
- ④에서 OpenAPI의 64비트 정수는 `type: string`(+ `pattern: '^-?[0-9]+$'`)으로 적는다. `type: integer, format: int64`는 생성기가 TS `number`로 만들어 2^53을 넘으면 값이 바뀐다.
- ⑥의 증거는 "타입 검사 통과"가 아니다. 같은 입력을 양쪽이 같은 값으로 읽었다는 실행 결과다.

## 3. 계약 변경 절차

정본을 바꾸는 PR은 아래 네 가지를 본문에 적는다. 하나라도 빠지면 리뷰하지 않는다.

```text
변경 제안   : 무엇을 왜 바꾸나 (소비자 작업 기준으로)
호환성 판정 : 추가(additive) | 깨짐(breaking) — 근거: oasdiff 출력 또는 매니페스트 diff
버전        : 유지 | REST /api/v2 | 스트림 STREAM_MSG_VERSION n → n+1
폐기 기간   : 구 버전을 언제까지 함께 제공하나, 소비자 전환 확인 방법
```

### 호환성 판정표

| 변경 | REST/JSON | 바이너리 스트림 |
|---|---|---|
| 응답 필드 추가 | 추가 — 소비자는 모르는 필드를 무시한다 | 추가 — 본문 끝에 덧붙이고 `body_len`으로 알린다 |
| 선택 요청 필드 추가 (기본값 있음) | 추가 | 해당 없음 |
| 예약 영역을 새 필드로 사용 (0 = 없음) | 해당 없음 | 추가 — 구 송신자는 0을 보낸다 |
| 새 메시지 종류·새 엔드포인트 | 추가 | 추가 — 구 수신자는 `body_len`만큼 건너뛴다 |
| enum 값 추가 | 소비자 기본 분기가 있으면 추가, 없으면 깨짐 | 같음 |
| 필드 제거·이름 변경 | **깨짐** | **깨짐** |
| 타입·크기·스케일·단위 변경 | **깨짐** | **깨짐** (가격 스케일 10^4 → 10^6 포함) |
| 필드 순서·오프셋·엔디언 변경 | 해당 없음 | **깨짐** |
| 필수 요청 필드 추가 | **깨짐** | 해당 없음 |

### 깨지는 변경 처리

- 깨지는 변경은 새 버전으로 낸다. REST는 `/api/v2`, 스트림은 헤더 `version`을 올린다.
- 구 버전과 새 버전을 폐기 기간 동안 함께 제공한다. 내부 소비자만 있으면 한 배포 주기, 외부 소비자가 있으면 합의한 기간(공개 API는 `api-design`의 6개월)이다.
- 폐기 기간이 끝나기 전에 소비자 전환을 확인한다. 확인 수단은 구 버전 요청 수 지표나 구 버전 연결 로그다.
- 스트림 수신자는 모르는 `version`을 받으면 추측해 해석하지 않는다. 연결을 끊고 재접속해 협상하거나 오류를 보고한다.

## 4. 깨지는 변경 검출 — CI에서 자동으로

사람의 판정은 놓친다. 정본 diff를 기계가 먼저 판정하고, 사람은 그 결과를 확인한다.

### REST — oasdiff

```bash
# 기준 브랜치의 정본과 비교한다. 깨지는 변경이 있으면 비0 종료
git show origin/main:api/openapi.yaml > /tmp/openapi.base.yaml
oasdiff breaking /tmp/openapi.base.yaml api/openapi.yaml --fail-on ERR
```

- `--fail-on ERR`은 깨지는 변경에서만 실패한다. 경고까지 막으려면 `WARN`을 쓴다.
- oasdiff가 깨짐으로 판정했는데 의도한 변경이면 3절 절차대로 새 버전을 낸다. 판정을 끄지 않는다.

### 바이너리 — 레이아웃 매니페스트 diff

C 헤더에서 매니페스트(필드 이름·오프셋·크기·타입·엔디언·버전)를 **생성**하고 커밋한다.
CI는 다시 생성해 커밋본과 비교한다. 매니페스트를 손으로 쓰면 정본이 둘이 되므로 금지한다.

```bash
bash src/contract/check-layout.sh     # 0 일치 · 1 드리프트 · 2 빌드 실패
git diff --stat -- src/contract/vectors/layout.json   # PR 리뷰에서 레이아웃 변경을 눈으로 본다
```

- 매니페스트 diff에서 기존 필드의 `offset`·`size`·`type`이 바뀌었으면 깨지는 변경이다.
- 새 필드만 늘었고 구조체 `size`가 커졌다면 추가 변경이다. 이 판정을 PR 본문에 적는다.
- 오프셋은 `offsetof`·`sizeof`로 생성기가 계산한다. 숫자를 손으로 적은 매니페스트는 증거가 아니다.

## 5. 스트림 계약

대용량 스트림의 정본은 C 헤더 구조체다. 서버는 할당·변환 없이 보내고, 클라이언트는 `DataView`로 직접 읽는다.

### 5.1 바이너리 스키마 규칙

- **엔디언은 채널마다 한 번만 적는다.** 헤더 파일 머리 주석 한 곳에 "모든 다중 바이트 필드는 리틀엔디언"처럼 적는다. 필드마다 다르게 하지 않는다.
- **인코딩은 필드별 명시 변환으로 한다.** 구조체를 `memcpy`로 통째 보내면 호스트 엔디언과 컴파일러 패딩에 기대게 된다. 오프셋은 `offsetof`로 얻고 바이트 단위 LE 헬퍼로 쓴다.
- **크기와 오프셋을 `_Static_assert`로 고정한다.** 구조체 크기와 모든 필드 오프셋을 단언한다. 바뀌면 컴파일이 멈춘다.
- **암묵 패딩을 두지 않는다.** 8바이트 필드는 8의 배수 위치에 두고, 남는 공간은 이름 있는 `reserved` 배열로 채운다.
- **모든 메시지는 공통 헤더로 시작한다.** 헤더에는 `version`·`msg_type`·`body_len`·`sequence`·송신 시각을 둔다. `body_len`이 있으면 TCP 위에서 스스로 프레이밍된다.
- **가격·수량은 스케일 정수(`int64`)다.** 스케일은 헤더 상수로 적는다. 부동소수점 필드는 두지 않는다. TS에서는 `getBigInt64`로 읽어 `bigint`로 보관하고, 표시할 때만 문자열로 바꾼다.
- **고정 길이 문자열은 ASCII + NUL 패딩이다.** 길이를 꽉 채우면 종료 NUL이 없다. 첫 NUL 뒤에 0이 아닌 바이트가 있으면 거부한다. 송신 측 초기화 누락이 여기서 드러난다.
- **예약 영역과 패딩은 0으로 보낸다.** 송신 측은 본문 전체를 0으로 채운 뒤 필드를 쓴다. 수신 측은 현재 버전에서 예약 영역을 읽지 않는다.
- **최대 메시지 크기를 정한다.** 수신 측은 `body_len`이 상한을 넘으면 버퍼를 잡기 전에 거부한다.

### 5.2 진화 규칙 — 추가만 허용

1. 새 메시지 종류를 추가한다. 구 수신자는 모르는 `msg_type`을 `body_len`만큼 건너뛴다.
2. 본문 끝에 필드를 덧붙인다. 구 수신자는 아는 크기까지만 읽고 나머지를 무시한다.
3. 예약 영역을 새 필드로 쓴다. 0은 "값 없음"이어야 한다. 구 송신자가 0을 보내기 때문이다.
4. 위 세 가지가 아니면 깨지는 변경이다. `version`을 올리고 3절 절차를 밟는다.

메시지 종류 번호와 필드 이름은 한 번 쓰면 재사용하지 않는다. 폐기한 번호는 헤더 주석에 남긴다.

### 5.3 채널 명세 템플릿

채널마다 아래 항목을 계약 문서(또는 헤더 머리 주석)에 적는다. 손실 정책 다섯 항목의 원칙은 `data-throughput-accelerator` 4·5절이다.

```text
채널          : <이름> — <송신자> → <수신자>, 전송 <TCP 포트 | WebSocket 경로>
정본          : <src/contract/xxx_msg.h>, 엔디언 <little>, 버전 <n>
메시지 종류   : <번호 이름 본문 구조체 크기> 한 줄에 하나
순서 보장     : <채널 전체 | 키별> — 시퀀스 범위 <채널 | 키>
손실 정책     : 전량 보존 | 최신값 병합(키: <필드>) | 샘플링(<주기·비율>)
가득 참 동작  : 대기 | 병합 | 드롭(오래된 것/새 것)
갭 처리       : 재요청 | 스냅샷 재동기화 | 무시
재동기화 절차 : <스냅샷 요청 방법> → 스냅샷 시퀀스 S 수신 → S 이후 증분만 적용
최대 메시지   : 헤더 <n> + 본문 <n> 바이트, 초과 시 <연결 종료>
하트비트      : <주기>, <n>회 연속 미수신 시 재접속
관측 지표     : 드롭 수·병합 수·갭 수·재동기화 수 카운터 이름
```

예제 채널을 채우면 이렇다.

```text
채널          : quote — 시세 서버 → 화면 클라이언트, TCP
정본          : templates/project/c-system/src/contract/stream_msg.h, 엔디언 little, 버전 1
메시지 종류   : 0 heartbeat 본문 없음 / 1 quote StreamQuote 48바이트
순서 보장     : 채널 전체 — header.sequence 단조 증가
손실 정책     : 최신값 병합(키: key)
가득 참 동작  : 병합 — 같은 key 의 이전 값을 덮어쓴다
갭 처리       : 스냅샷 재동기화
재동기화 절차 : 재접속 → 스냅샷(현재 키별 값과 시퀀스 S) → sequence > S 인 quote 만 적용
최대 메시지   : 헤더 24 + 본문 4096 바이트, 초과 시 연결 종료
하트비트      : 1초, 3회 연속 미수신 시 재접속
관측 지표     : quote_merge_total, quote_gap_total, quote_resync_total
```

길이 prefix 프레이밍(`stream-pipeline-patterns` 5절의 `frame_codec`)을 함께 쓰면 그 길이 필드도 채널 명세에 적는다. 한 채널 안에서 엔디언이 둘이 되지 않게 한다.

### 5.4 C ↔ TS 상호 검증 — 공유 테스트 벡터

컴파일 타입이 맞아도 오프셋 하나가 틀리면 값이 조용히 어긋난다. 같은 바이트를 양쪽이 같은 값으로 읽는지 실행해 확인한다.

1. C 생성기가 정본 헤더로 벡터(`*.bin`)와 기댓값(`cases.json`)과 매니페스트(`layout.json`)를 만든다.
2. 기댓값 JSON의 64비트 정수는 문자열로 적는다. JSON 숫자는 2^53을 넘으면 값이 바뀐다.
3. C 테스트는 커밋된 벡터를 읽는다. 디코더를 고쳐도 이미 나간 메시지를 읽을 수 있음을 확인한다.
4. TS 테스트는 디코더 상수를 `layout.json`과 하나씩 대조하고, 모든 벡터를 디코드해 `cases.json`과 비교한다.
5. 벡터에는 경계값을 넣는다: 2^53 초과, `INT64_MIN`·`INT64_MAX`, 꽉 찬 키, 최대 시퀀스, 미래 버전이 덧붙인 꼬리 필드, 하트비트.
6. 거부 경로도 양쪽에서 같은 이름으로 확인한다: 짧은 입력 `EMSGSIZE`, 버전 불일치 `EPROTO`, 상한 초과 `EOVERFLOW`, 키 오염 `EBADMSG`.
7. Rust로 이식하면 같은 벡터를 Rust 테스트에도 붙인다. 구조체는 `#[repr(C)]`와 `const _: () = assert!(size_of::<T>() == N);`로 고정한다.

### 5.5 실행 가능한 예제

`templates/project/c-system/src/contract/`가 이 절의 규칙을 그대로 구현한다.

| 파일 | 내용 |
|---|---|
| `stream_msg.h` | 정본 — 헤더 24바이트·`StreamQuote` 48바이트, 오프셋 `_Static_assert`, 스케일·상한 상수 |
| `stream_msg.c` | 필드별 리틀엔디언 인코드·디코드, 키 패딩 검사, 꼬리 필드 무시 |
| `gen_vectors.c` | X-매크로 필드 표로 `layout.json`·`cases.json`·`*.bin` 생성 |
| `test_stream_msg.c` | 알려진 바이트 열 해석, 경계값 왕복, 패딩 0, 거부 경로, 커밋된 벡터 해석 |
| `ts/decode.ts` | `DataView`·`bigint` 디코더, `FormatScaled`(부동소수점 없는 표시) |
| `ts/decode.test.ts` | 매니페스트 대조, 벡터 값 비교, 거부 경로, 모르는 메시지 종류 건너뛰기 |
| `check-layout.sh` | 재생성 결과와 커밋된 `vectors/` 비교 — 레이아웃 드리프트 검출 |
| `Makefile` | `make test`(ASan+UBSan)·`make vectors`·`make layout`·`make ts-test`·`make check` |

TS 테스트는 `node --test ts/decode.test.ts`로 돈다. Node 22.18·23.6 이상은 타입 제거가 기본이라 `tsc` 없이 실행된다. 그보다 낮은 22.x는 `--experimental-strip-types`를 붙인다. 디코더는 열거형·매개변수 속성 같은 변환이 필요한 TS 문법을 쓰지 않는다.

## 6. 안티패턴

| 안티패턴 | 증상 | 바로잡기 |
|---|---|---|
| 제공자 추측 구현 | 서버가 "클라이언트가 이걸 원할 것"이라며 필드를 먼저 만든다 | ①② 단계로 소비자 작업을 먼저 적는다 |
| 소비자 추측 구현 | 클라이언트가 서버 응답 예시 하나를 보고 타입을 손으로 만든다 | 정본에서 생성하거나 대조 테스트를 붙인다 |
| 정본 중복 | 위키 표·TS 인터페이스·C 헤더가 각자 고쳐진다 | 정본 하나를 정하고 나머지는 생성물로 바꾼다 |
| 손으로 쓴 매니페스트 | 헤더는 바뀌었는데 매니페스트는 그대로다 | `offsetof`로 생성하고 CI에서 diff한다 |
| 컴파일 타입만으로 검증 | `tsc` 통과를 계약 준수로 본다 | 같은 벡터를 양쪽이 같은 값으로 읽는 실행 증거를 낸다 |
| 구조체 통째 `memcpy` 송신 | 다른 아키텍처·컴파일러에서 값이 바뀐다 | 필드별 명시 엔디언 변환 |
| 가격을 JS `number`로 변환 | `Number(bigint)`·`parseFloat`로 자릿수가 사라진다 | `bigint`·문자열 보관, 표시할 때만 포맷 |
| 판정 없는 버전 올리기 | 추가 변경인데 버전을 올려 모든 소비자를 끊는다 | 3절 판정표로 먼저 판정한다 |
| 모르는 버전을 추측 해석 | 새 레이아웃을 구 디코더로 읽어 쓰레기 값을 표시한다 | `EPROTO`로 거부하고 재접속·보고한다 |
