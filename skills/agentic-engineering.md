# 에이전트 엔지니어링

AI 에이전트가 구현 작업 대부분을 수행하고, 사람이 품질·리스크 통제를 강제하는
엔지니어링 워크플로를 위한 스킬. **하네스를 직접 설계·운영하는 관점**을 익히는 메타 스킬이다.

> Arachne의 기존 규칙과 연결: 모델 선택은 [performance.md](../rules/common/performance.md),
> 에이전트 활성화는 [agents.md](../rules/common/agents.md),
> 개발 파이프라인은 [development-workflow.md](../rules/common/development-workflow.md) 참고.
> 이 스킬은 그 위에서 "어떻게 작업을 쪼개고·측정하고·라우팅할지"의 운영 원칙을 담는다.

## 언제 활성화하나

- 여러 단계의 복잡한 작업을 에이전트에 위임할 때
- 하네스(에이전트·커맨드·훅) 자체를 설계·개선할 때
- 모델 비용과 품질을 균형 맞춰야 할 때
- AI 생성 코드의 리뷰 초점을 정해야 할 때

## 운영 원칙

1. **실행 전에 완료 기준을 정의한다.** — 무엇이 "done"인지 모르면 위임하지 않는다.
2. **작업을 에이전트 크기 단위로 분해한다.**
3. **작업 복잡도에 따라 모델 티어를 라우팅한다.**
4. **eval과 회귀 검사로 측정한다.** — 인상이 아닌 델타로 판단.

## Eval-우선 루프

```
1. 능력(capability) eval + 회귀(regression) eval 정의
2. 베이스라인 실행 → 실패 시그니처 포착
3. 구현 실행
4. eval 재실행 → 델타 비교
```

> 측정 가능한 기준이 없으면 "잘 된 것 같다"는 환상에 빠진다. 변경 전후를 같은 잣대로 비교한다.

## 작업 분해 — 15분 단위 규칙

각 단위는:

- **독립적으로 검증 가능**해야 한다
- **단일 지배 리스크**만 가져야 한다 (한 단위에 위험을 몰지 않음)
- **명확한 done 조건**을 노출해야 한다

> 큰 작업을 한 번에 위임하면 실패 원인을 특정할 수 없다. 검증 가능한 최소 단위로 쪼갠다.
> 이슈 처리의 단계적 구현(Phase 1→2→3)과 같은 사고다 — [/issue 커맨드](../commands/issue.md) 참고.

## 모델 라우팅

| 티어 | 용도 |
| ---- | ---- |
| **Haiku** | 분류, boilerplate 변환, 좁은 범위 편집 |
| **Sonnet** | 일반 구현·리팩터링, 코드 리뷰 |
| **Opus** | 아키텍처, 근본 원인 분석, 다중 파일 불변식, 저수준 시스템 설계 |

> Arachne 에이전트 모델 배정과 일치: `planner`=opus, `code-reviewer`·`tdd`·`debugger`=sonnet.
> 자세한 전략은 [performance.md](../rules/common/performance.md).

## 세션 전략

- **세션 유지** — 밀접하게 결합된 단위들 사이
- **새 세션 시작** — 주요 단계(phase) 전환 후
- **압축(compact)** — 마일스톤 완료 후. **활성 디버깅 중에는 압축 금지** (컨텍스트 손실 위험)

> 세션 상태 저장은 `/save-session`·`/handoff` 커맨드 활용.

## AI 생성 코드 리뷰 초점

우선순위:

- 불변식(invariant)과 엣지 케이스
- 에러 경계(error boundary)
- 보안·인증 가정
- 숨겨진 결합과 롤아웃 리스크

자동 포매터·린터가 이미 스타일을 강제한다면, **스타일만의 이견에 리뷰 사이클을 낭비하지 않는다.**
이 초점은 `code-reviewer` 에이전트의 "신뢰도 기반 필터링"과 정렬된다.

## 비용 규율

작업마다 추적:

- 모델
- 토큰 추정치
- 재시도 횟수
- 실제 소요 시간(wall-clock)
- 성공/실패

> **에스컬레이션 규칙**: 하위 티어가 **명확한 추론 격차로 실패할 때만** 상위 모델로 올린다.
> 처음부터 Opus를 기본값으로 쓰지 않는다 — 결정론적 리팩터링·단순 편집은 Sonnet 이하로 충분하다.

## 하네스 설계에 적용

이 스킬을 Arachne 자체에 적용하는 관점:

- **에이전트** = 에이전트 크기 단위로 분해된 작업의 실행자 (단일 책임·명확한 done)
- **커맨드** = 반복되는 워크플로를 고정한 진입점
- **훅** = 사람이 강제하는 품질·리스크 게이트의 자동화
- **rules** = 모든 위임에 적용되는 불변 제약

새 에이전트·커맨드를 추가할 때 묻는다: "이게 검증 가능한 단일 단위인가? done 조건이 명확한가?
어느 모델 티어가 맞는가?" — 그렇지 않으면 더 쪼갠다.
