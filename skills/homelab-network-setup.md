# 홈랩 네트워크 설정

재구축 없이 성장할 수 있는 홈 또는 소규모 랩 네트워크를 설계할 때 사용한다.

## 언제 사용하나

- 새 홈 네트워크 계획 또는 ISP 라우터 전용 설정 재설계
- 게이트웨이·스위치·AP 역할 선택
- IP 범위·DHCP 범위·정적 예약·DNS 설계
- 향후 VLAN, Pi-hole, NAS, 랩 서버, VPN 접근 준비
- 이중 NAT, 불안정한 Wi-Fi, 변경되는 서버 주소가 있는 새 네트워크 문제 해결

## 작동 방식

장치 역할 분리부터 시작:

```text
인터넷
  |
모뎀 또는 ONT
  |
게이트웨이/라우터     NAT, 방화벽, DHCP, DNS, 인터-VLAN 라우팅
  |
매니지드 스위치       유선 클라이언트, AP 업링크, 선택적 VLAN 트렁크
  |
AP                   Wi-Fi 전용; 가능하면 유선 백홀
서버·NAS             안정적인 주소, DNS 이름, 모니터링
클라이언트·IoT        DHCP 풀, 추후 VLAN 격리
```

기능 체크리스트보다 운영자에 맞는 게이트웨이 선택:

| 옵션 | 적합 | 비고 |
|---|---|---|
| ISP 라우터 | 기본 인터넷만 | 제어 제한, VLAN 지원 빈약 |
| UniFi 게이트웨이 | 관리형 홈 네트워크 | 좋은 UI, 에코시스템 종속 |
| OPNsense/pfSense | 유연한 홈랩 | VLAN·방화벽·VPN·DNS 강력 지원 |
| MikroTik | 고급 사용자 | 강력하지만 잘못 설정하기 쉬움 |
| Linux 라우터 | 실험적 사용 | 주 게이트웨이로 사용 전 롤백 문서화 |

## IP 계획

VPN 사용이 예상될 때 가장 흔한 기본값 `192.168.1.0/24` 사용 금지
(호텔, 사무실, ISP 라우터와 자주 충돌).

```text
소규모 홈랩 계획 예시:

192.168.10.0/24  신뢰할 수 있는 클라이언트
192.168.20.0/24  IoT 및 미디어 장치
192.168.30.0/24  서버 및 NAS
192.168.40.0/24  게스트 Wi-Fi
192.168.99.0/24  네트워크 관리

게이트웨이 관례: .1
인프라 예약: .2 ~ .49
동적 DHCP 풀: .50 ~ .240
여유 공간: .241 ~ .254
```

로컬 이름에는 `home.arpa` 사용. 홈 네트워크용으로 예약되어 있으며
`home.lan` 같은 임시 이름의 누출/충돌 문제를 피한다.

```text
nas.home.arpa
pihole.home.arpa
gateway.home.arpa
switch-01.home.arpa
```

## DHCP 및 DNS

- SSH 접속·북마크·모니터링·서비스 노출 대상에는 DHCP 예약 사용
- 로컬 리졸버 의도적 배포 전까지 DNS로 게이트웨이 제공
- Pi-hole 또는 다른 DNS 필터 사용 시 먼저 예약 부여 후 DHCP DNS 옵션을 해당 주소로 지정
- 교체 시 동적 임대와 충돌하지 않도록 서브넷별 소규모 정적/예약 범위 유지

## 케이블링 및 Wi-Fi

- 이더넷을 사용할 수 있을 때 메시 대신 유선 AP 백홀 권장
- 예산이 허용하면 AP와 카메라에 PoE 스위치 사용
- 각 케이블의 양쪽에 레이블 부착, 간단한 포트 맵 유지
- 정전이 자주 발생하면 게이트웨이·스위치·DNS 서버·NAS를 UPS 전원에 연결

## 예시

### 초보자 업그레이드

목표: ISP 라우터 유지하며 소규모 랩 안정화.
1. NAS, Pi, SSH 호스트에 DHCP 예약 설정
2. 로컬 이름을 `home.arpa`로 이동
3. 보조 라우터 또는 AP의 중복 DHCP 서버 비활성화
4. 무선 백홀 대신 메인 AP 유선 연결

### VLAN 준비 계획

목표: 즉시 활성화하지 않고 향후 분할 준비.
1. 신뢰할 수 있는, IoT, 서버, 게스트, 관리를 위한 겹치지 않는 /24 범위 선택
2. 모든 서브넷에서 게이트웨이용 .1과 인프라용 .2-.49 예약
3. VLAN과 인터-VLAN 방화벽 규칙을 지원하는 게이트웨이·스위치 구매
4. 각 네트워크에 결국 매핑될 SSID와 스위치 포트 문서화

## 안티패턴

- 이유나 문서 없이 이중 NAT
- VPN 접근 계획 시 `192.168.1.0/24` 사용
- NAS, Pi-hole, Home Assistant, 기타 서비스 호스트에 동적 주소
- DHCP 서버가 여전히 활성화된 AP로 재활용된 소비자 라우터
- 카메라·스마트 플러그·노트북·서버가 같은 신뢰 경계를 공유하는 평탄한 네트워크
