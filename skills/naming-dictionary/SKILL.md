# 네이밍 사전 — 약어와 용어 통일

같은 개념은 같은 단어로 쓴다. 줄여 쓰는 단어는 사전에 등록된 약어만 쓴다.
사전은 프로젝트가 소유하고(`.arachne/naming-dict.tsv`), 하네스는 형식·기본 약어·검사 도구만 준다.
검사는 **보고만** 하고 차단하지 않는다. 대상은 새로 쓰거나 바꾼 식별자뿐이다.

## 언제 사용하나

- 새 모듈·구조체·함수 이름을 정할 때
- 리뷰에서 "같은 개념이 `Cnt`·`Count`·`Num`으로 섞여 있다"는 지적이 나올 때
- 새 약어를 쓰고 싶을 때 (먼저 사전에 등록한다)
- `/verify`가 `naming-check` 경고를 보고했을 때

### 언제 사용하지 않나

- 기존 코드 일괄 이름 변경 — 하지 않는다. 기존 파일은 기존 관례를 따른다
- 외부 API·DB 컬럼·프로토콜 필드 이름 — 외부 정의가 정본이다
- Rust 공개 API — Rust API Guidelines가 우선이다. 약어 사전은 내부 이름에만 적용한다

## 사전 형식

탭으로 구분한 TSV다. 첫 줄은 머리글, `#`으로 시작하는 줄은 주석이다.

| 열 | 내용 | 예 |
|---|---|---|
| 표준 단어 | 개념을 대표하는 영어 단어 (소문자) | `count` |
| 허용 약어 | 이 단어 대신 쓸 수 있는 약어. 없으면 빈 칸 (전체 단어만 쓴다) | `Cnt` |
| 의미 | 한국어 뜻. 같은 단어를 다른 뜻으로 쓰지 않게 범위를 적는다 | `개수` |
| 금지 동의어 | 쓰면 안 되는 다른 표기. 쉼표로 여러 개 | `cnts` |
| 분류 | 공통·통신·업무·시스템·데이터 등 | `공통` |

```text
표준 단어	허용 약어	의미	금지 동의어	분류
count	Cnt	개수	cnts	공통
response	Rsp	응답	resp,res	통신
order	Ord	주문	ordr	업무
```

- 템플릿은 `templates/project/naming-dict.tsv`다. 공통 기본 약어 25개가 들어 있다.
- 프로젝트는 이 파일을 `.arachne/naming-dict.tsv`로 복사해 고친다. 복사한 뒤에는 프로젝트 소유다.
- 대소문자는 구분하지 않는다. `Cnt`·`cnt`·`CNT`는 같은 약어다.

## 약어 원칙

1. **자주 쓰는 긴 단어만 줄인다.** `index`→`Idx`는 이득이 있다. `id`·`key`·`name`은 줄이지 않는다.
2. **3~5자로 줄인다.** 2자 약어는 뜻이 겹치기 쉽다. 예외는 `Ts`처럼 업계에서 굳은 것뿐이다.
3. **앞부분을 유지한다.** 모음만 빼는 것보다 앞부분을 남기는 쪽이 읽기 쉽다.
   `configuration`→`Cfg`처럼 관례가 굳은 것은 예외로 사전에 적는다.
4. **한 단어에 약어 하나.** `response`를 `Rsp`로 정했으면 `Resp`·`Res`는 금지 동의어에 넣는다.
5. **한 약어에 단어 하나.** `Res`가 `response`와 `resource`를 동시에 뜻하면 안 된다.
6. **약어를 정했으면 전체 단어와 섞지 않는다.** `Cnt`를 정한 프로젝트에서 새 이름에 `Count`를 쓰지 않는다.

## 식별자 구성 순서

**도메인 → 대상 → 동작/속성** 순서로 붙인다. 같은 도메인의 이름이 정렬했을 때 모인다.

| 종류 | 형식 | 예 |
|---|---|---|
| 함수 | `<도메인><대상><동작>` | `OrdBookInsert`, `OrdBookFind`, `AcctBalGet` |
| 전역 변수 | `g_<도메인><대상>` | `g_OrdBookList`, `g_ShmSegCnt` |
| 구조체 | `<도메인><대상>` | `OrdBook`, `MktDataMsg` |
| 상수·매크로 | `<도메인>_<대상>_<속성>` | `ORD_BOOK_MAX_CNT`, `MSG_HDR_LEN` |
| 지역 변수 | `<대상>_<속성>` | `ord_cnt`, `msg_len`, `rec_idx` |

- 위 예의 `Bal`·`Mkt`·`Shm`·`Hdr`은 프로젝트 사전에 등록했다고 가정한 약어다.
- 조회·변경 함수 동사는 프로젝트 안에서 통일한다. 예: `Find`·`FindRange`·`Insert`·`Remove`.
  같은 뜻으로 `Get`·`Search`·`Lookup`을 섞지 않는다.
- C에서 불투명 핸들을 쓰면 핸들 타입 이름이 도메인 접두가 된다(`OrdBook` → `OrdBookCreate`·`OrdBookDestroy`).

## 공통 접두·접미

| 형태 | 뜻 | 예 |
|---|---|---|
| `g_` | 전역 변수 | `g_SessionList` |
| `m_` | C++ 클래스 멤버 | `m_conn_cnt` |
| `Is`·`Has`·`Can` | 참·거짓을 돌려주는 함수·변수 | `IsReady`, `HasPendingMsg` |
| `Cnt` | 개수 | `ord_cnt` |
| `Len` | 바이트·문자 길이 | `msg_len` |
| `Idx` | 배열·목록 위치 | `rec_idx` |
| `Max`·`Min` | 한계값 | `MAX_CONN_CNT` |
| `Buf` | 임시 저장 메모리 | `rsp_buf` |
| `Ptr` | 포인터임을 강조해야 할 때만 | `seg_ptr` |

- 단위가 있는 값은 단위를 접미로 붙인다. 예: `timeout_ms`, `size_bytes`, `price_tick`.
- `Cnt`(개수)와 `Len`(길이)과 `Size`(바이트 크기)를 섞어 쓰지 않는다.

## 신규 약어 등록 절차

1. `naming-check`가 `미등록약어`를 보고하면, 먼저 전체 단어로 쓸 수 있는지 본다.
2. 약어가 필요하면 사전에 한 줄을 추가한다. 다섯 열을 모두 채우고, 금지 동의어도 적는다.
3. 같은 약어나 같은 표준 단어가 이미 있는지 확인한다(한 단어 한 약어, 한 약어 한 단어).
4. 사전 변경은 그 약어를 처음 쓰는 코드와 **같은 커밋**에 넣는다. 리뷰어가 함께 본다.
5. 프로젝트 고유 단어는 사전의 "프로젝트 영역" 아래에 모은다.

## 검사 도구 — `lib/naming-check.sh`

```bash
bash ~/.claude/lib/naming-check.sh --changed          # 변경된 줄의 식별자만 (기본)
bash ~/.claude/lib/naming-check.sh --all src/         # 지정 경로 전체
bash ~/.claude/lib/naming-check.sh --all --strict     # 경고가 있으면 종료 코드 1
```

- 대상 언어는 C·C++·Pro*C(`.pc`)·ecpg(`.pgc`)·Rust·TypeScript다.
- 식별자 추출은 universal-ctags가 있으면 그것을 쓰고, 없으면 정규식으로 선언문을 찾는다.
  주석·문자열·`EXEC SQL` 문 안의 이름은 검사하지 않는다.
- 단어 분해는 `g_`·`m_` 접두를 떼고, `_`와 대소문자 경계(PascalCase·camelCase)로 나눈다.
- 사전은 `--dict <파일>`로 바꿀 수 있다. 기본값은 `.arachne/naming-dict.tsv`이며, 없으면 검사를 건너뛴다.

| 보고 | 뜻 | 조치 |
|---|---|---|
| `미등록약어` | 사전·일반 영어 목록에 없는 짧은 단어(3자 이하, 또는 첫 글자 뒤 모음이 없는 4~5자) | 전체 단어로 쓰거나 사전에 등록 |
| `금지동의어` | 사전의 금지 동의어 사용 (`Resp`) | 표준 단어나 허용 약어로 교체 |
| `동의어혼용` | 같은 표준 단어의 전체 단어와 약어가 함께 쓰임 (`Count`·`Cnt`) | 사전 약어로 통일 |
| `길이초과` | 30자 초과 | 도메인 접두나 중복 단어를 줄임 |

- 기본은 보고만 하고 종료 코드 0이다. CI에서 막지 않는다.
- `--changed`는 `git diff`의 추가 줄과 추적되지 않은 새 파일만 본다. 기존 코드는 경고하지 않는다.
- 동의어 혼용은 검사한 식별자 사이에서만 판단한다. 전체 현황은 `--all`로 따로 확인한다.

## 적용 범위

- 대상은 **신규·변경 식별자**뿐이다. 기존 코드를 사전에 맞추려고 이름을 바꾸지 않는다.
- 기존 파일을 고칠 때는 그 파일의 기존 관례를 따른다. 사전과 충돌하면 기존 관례가 이긴다.
- 리뷰어는 새 식별자의 사전 위반을 지적할 수 있다. 차단 사유는 아니다.
