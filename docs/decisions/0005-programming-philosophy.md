# ADR-0005: 시스템 프로그래밍 철학 결정 — 원칙 층 충돌 정리

## 상태

Accepted (2026-10-05)

## 배경

Arachne의 도구·검증 층(sanitizer, clippy, miri, 퍼징)은 시스템 프로그래밍에 잘 맞지만, 규칙 문장
자체에는 세 가지 문제가 있었다.

첫째, 매 세션 로드되는 `rules/common`에 웹 개발에서 온 "불변성 절대 원칙"이 들어 있어, 시스템
코드에서 정상적인 제자리 갱신을 리뷰어가 결함으로 지적한다. 둘째, `strncpy`를 안전한 대체재로
권하는 것처럼 틀린 코드를 유도하는 문장이 있다. 셋째, 동시성·성능·디버깅 방법론에 대한 원칙이
비어 있다.

이 문제를 정리하려면 대가들 사이에서도 입장이 갈리는 지점을 먼저 정해야 한다. 그 목록이
`programming-philosophy.md`의 결정 레지스터(D01~D17)와 통합 계획의 하네스 고유 결정(D18~D23)이다.

## 결정

대부분은 문서가 제시한 기본·권장안을 채택한다. 이 하네스의 실제 사용 방식(C 주력, Pro*C·ecpg
임베디드 SQL, 공유메모리 기반 데이터 계층, 한국어 문서·커밋)과 맞지 않는 네 가지만 다르게 정한다.

| 결정 | 선택 | 기본안과 다른 이유 |
| --- | --- | --- |
| D01 기존 관례 vs 철학 | **혼합** — 스타일은 기존 관례, 안전성·에러 처리·동시성은 철학 우선 | 기존 Pro*C·C 자산이 있어 스타일 일괄 변경은 비용만 크다 |
| D12 동시성 모델 | 메시지 패싱 우선 **+ 락 기반 공유 상태 허용** | 공유메모리 ⇄ DB 데이터 계층이 공유 가변 상태를 전제로 한다. 락 순서와 robust 뮤텍스 복구 규칙을 문서화하는 조건 |
| D14 매크로 | C 함수형 매크로 금지, **단 두 가지 예외** | C에는 대체 수단이 없다. 호출 위치를 담는 로그 매크로(`__FILE__`·`__LINE__`)와 필드 정의 X-매크로 테이블만 허용 |
| D17 주석·커밋 언어 | **전부 한국어** | 하네스의 커밋 규약과 파일·함수 헤더가 이미 한국어다 |

그 밖의 결정은 다음과 같다.

| 결정 | 선택 |
| --- | --- |
| D02 포매팅 | 저장소 `.clang-format`, 없으면 LLVM |
| D03 C++ 에러 | 경로 분리 — 핫패스는 `noexcept` + 에러 값 |
| D04 Rust 에러 | 라이브러리 `thiserror`, 앱 최상위 `anyhow` |
| D05 불변식 위반 | 계층 분리 — 개발 빌드는 즉시 중단, 운영은 해당 요청만 실패 처리 |
| D06 최적화 시점 | 경로 기반 — 핫패스는 코드 주석 `/* HOTPATH */`·`// HOTPATH`로 표시 |
| D07 자료구조 | 표준 컨테이너 우선 (C는 `c-data-structures` 스킬 기준) |
| D08 이식성 | 서버 티어는 리눅스 전용 허용(격리 필수), 클라이언트는 런타임 이식성에 위임 |
| D09 데이터 형식 | 경계별 — 설정·로그는 텍스트, 핫패스 프로토콜은 바이너리 |
| D10 내부 API | 커널 방식 — 외부 인터페이스만 호환 유지 |
| D11 Rust `unsafe` | 격리 허용 + `// SAFETY:` 필수 |
| D13 Rust 비동기 | 용도 분리 — 주변부 Tokio, 핫패스 전용 스레드 |
| D15 테스트 | 기능과 테스트를 같은 변경에, 버그 수정은 재현 테스트 먼저 |
| D16 언어 표준 | C11 / C++20 / Rust 2024 |
| D18 불변성 | 언어별 분리 — 절대 원칙은 JS·Python 규칙으로, 핫패스 예외 명시 |
| D19 네이밍 | C/C++ 하우스 스타일 유지, Rust는 생태계 관용. `ii` 규칙과 `_t` 접미사 폐지. 약어는 프로젝트 사전 기준 |
| D20 헤더 | 축소 — 날짜 필드 삭제, 함수 헤더는 공개 API·비자명 함수만 |
| D21 테스트 강제 | 수치 기준(80%)은 신규 모듈에만 |
| D22 지연 스킬 | 웹 지연과 프로세스 내부 핫패스로 분리 |
| D23 철학 배치 | `rules/systems/` 신설, paths 지연 로드 |

## 대안

- **기본안 전부 채택**: 결정은 빠르지만, D12를 기본안대로 두면 공유메모리 설계가 "예외"로만
  취급되고 D17을 기본안대로 두면 커밋 언어가 하네스 규약과 충돌한다. 기각했다.
- **철학을 `rules/common`에 배치**: 웹 작업에도 매 세션 로드되어 컨텍스트 비용만 늘어난다. 기각했다.

## 결과

- 실행은 [Arachne 보강 로드맵](../task/20261005/2026-10-05-arachne-roadmap.md)의 트랙 A로 진행한다.
  철학 계획 P1~P5는 로드맵 웨이브 W1~W5에 대응한다.
- 철학 계획 문서의 결정 체크와 로드맵 연동 개정(R1~R8)은
  [통합 계획](../task/20261005/2026-09-29-programming-philosophy-integration.md) §6에 있다.
- 입력되지 않은 전제(C++ 표준, 회사·개인 코드 구분)는 가정으로 진행하며, 입력되면 이 ADR을
  supersede하는 새 ADR로 바꾼다.
