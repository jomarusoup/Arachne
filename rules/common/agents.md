# 에이전트 오케스트레이션

## 사용 가능한 에이전트

`~/.claude/agents/` 에 위치:

| 에이전트 | 목적 | 활성화 시점 |
|---|---|---|
| `planner` | 구현 설계·단계 분해 | 복잡한 기능, 대규모 리팩터링, 시스템 레벨 변경 |
| `code-reviewer` | 코드 품질·보안·안정성 검토 | 코드 작성·수정 직후 |
| `tdd` | TDD 가이드 (예정) | 신규 기능, 버그 수정 |
| `debugger` | 저수준 디버깅 (예정) | 빌드 실패, 런타임 오류, 메모리 문제 |

## 즉시 활성화 기준

별도 지시 없이 자동 활성화:

| 상황 | 에이전트 |
|---|---|
| 파일 3개 이상 수정 / 신규 모듈 도입 | **planner** |
| 시스템 레벨 변경 (IPC, 데몬, 커널 인터페이스) | **planner** |
| 코드 작성·수정 완료 | **code-reviewer** |
| 빌드 실패 / 메모리 오류 / 세그폴트 | **debugger** (예정) |
| 신규 기능 구현 시작 | **tdd** (예정) |

## 병렬 실행

독립적인 작업은 병렬로 에이전트 실행:

```
# GOOD: 병렬 실행
에이전트 3개 동시 실행:
1. Agent 1 — ipc 모듈 보안 분석
2. Agent 2 — daemon 모듈 성능 검토
3. Agent 3 — config 파싱 코드 리뷰

# BAD: 독립 작업을 순차 실행
Agent 1 완료 후 → Agent 2 → Agent 3
```

## Gemini와의 역할 분리

에이전트 위임 전에 Claude/Gemini 역할 확인:

- 설계·기획·README → **Gemini** (`gemini -p "..."`)
- 구현·리뷰·디버깅 → **Claude 에이전트**

자세한 역할 분담: `rules/common/workflow.md` 참고
