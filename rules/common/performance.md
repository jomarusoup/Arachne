# 성능 최적화

## 모델 선택 전략

작업 특성에 맞는 모델을 선택해 비용과 품질을 균형 있게 사용:

**Haiku** (빠른 응답, 저비용):
- 단순 커밋·푸시 작업
- 정형화된 코드 생성 (boilerplate)
- 멀티 에이전트 시스템의 워커 에이전트

**Sonnet** (기본 개발 모델):
- 일반적인 코드 구현·버그 수정
- 코드 리뷰 (`code-reviewer` 에이전트)
- 멀티 에이전트 오케스트레이터

**Opus** (깊은 추론 필요):
- 저수준 시스템 설계 (IPC, 데몬, 커널 인터페이스)
- 복잡한 아키텍처 결정
- 메모리·레이스 컨디션 원인 분석
- `planner` 에이전트 (기본값)

> 결정론적 리팩터링·단순 편집은 Sonnet 이하로 충분.
> Opus는 판단이 필요한 시스템 설계·분석 작업에 집중.

## 컨텍스트 창 관리

컨텍스트 창의 마지막 20% 구간에서 피해야 할 작업:

- 대규모 리팩터링 (파일 다수 수정)
- 여러 파일에 걸친 기능 구현
- 복잡한 상호작용 디버깅

컨텍스트 민감도가 낮은 작업 (언제든 가능):
- 단일 파일 편집
- 독립적인 유틸리티 작성
- 문서 업데이트
- 간단한 버그 수정

## 토큰 절약

- 파일 전체 읽기 금지 — `sgrep`으로 위치 먼저, 필요 범위만 `Read`
- Gemini 결과 재분석 금지 — 설계 결과를 바로 구현
- 병렬 에이전트 활용 — 독립 작업은 동시 실행

## 빌드 실패 대응

빌드 실패 시:

1. `debugger` 에이전트 활용 (예정)
2. 에러 메시지 단계적 분석
3. 수정 후 즉시 검증
4. 동일 패턴 재발 방지
