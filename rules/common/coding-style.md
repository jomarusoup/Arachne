# 공통 코딩 스타일

> 언어별 세부 규칙은 `rules/<언어>/coding-style.md` 참고.
> 이 파일은 모든 언어에 공통으로 적용되는 원칙만 담는다.

## 파일·함수 헤더 구조

모든 소스 파일에 파일 헤더를 둔다. 함수 헤더는 공개 API와 동작이 자명하지 않은 함수에만 둔다.
**형태는 동일하게, 주석 문자는 언어에 맞게.** Rust는 `//!`(모듈)·`///`(항목) 문서 주석으로 대신한다.

### 헤더 계층

| 단계 | 형태 | 용도 |
| --- | --- | --- |
| 파일 헤더 | `/*###...###*/` 또는 `####...####` | 파일 상단 메타 정보 |
| 함수 헤더 | `/*===...===*/` 또는 `#===...===` | 함수 역할·파라미터·반환값 |
| 특정 로직 | `/*---...---*/` 또는 `#---...---` | 함수 내 의미 있는 블록 |
| 일반 주석 | `//` 또는 `#` | 한 줄 설명 |

### 파일 헤더 필드

```
FILE NAME   : 파일명.확장자
DESCRIPTION : 파일 역할 한 줄 요약
```

날짜 필드는 두지 않는다. 작성·수정 이력은 git이 정본이다.

### 함수 헤더 필드

```
FUNCTION    : 함수명
DESCRIPTION : 역할 설명
PARAMETERS  : type 인자명 - 설명
RETURNED    : 반환값 설명 (void·None이면 생략)
```

## 네이밍

| 형식 | 예시 | 적용 대상 |
| --- | --- | --- |
| `snake_case` | `task_count` | 지역 변수, 함수 인자 |
| `g_SnakeCase` | `g_UserList` | 전역 변수 |
| `PascalCase` | `GetTaskList` | 함수·메서드, 타입, 클래스 |
| `SCREAMING_SNAKE_CASE` | `MAX_RETRY_COUNT` | 상수, 매크로, 환경변수 |
| `camelCase` | `taskCount` | JS 객체 속성, JSON 키 |

위 표는 C/C++ 하우스 스타일이다. Rust는 Rust API Guidelines를, 기존 파일은 기존 관례를 따른다.

공통 규칙:
- 최대 30자. 약어는 프로젝트 사전 등록분만 (→ `naming-dictionary`)
- 길이는 스코프에 비례 — 루프 인덱스 `i`·`j`는 허용, 넓은 스코프의 `a`·`b` 같은 이름은 금지

## 변수 선언

- 한 줄에 변수 하나만 선언
- 전역 변수는 반드시 초기값 지정
- 관련 변수는 열 맞춤(column alignment)

## 포매팅

- 들여쓰기: **4 스페이스** (탭 문자 금지)
- 줄 끝 공백 제거
- 파일 끝 빈 줄 1개

## 디버그 출력

디버그 출력은 prefix를 붙여 일반 로직과 구분:

| prefix | 용도 |
| --- | --- |
| `[DEBUG]` | 임시 디버그 — 배포 전 반드시 제거 |
| `[프로젝트명]` | 운영 경고·알림 — 유지 가능 |
