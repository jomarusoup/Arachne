# 보안 규칙

## 커밋 전 필수 체크리스트

- [ ] 하드코딩된 비밀값 없음 (API 키, 비밀번호, 토큰)
- [ ] 모든 사용자 입력 검증
- [ ] SQL 인젝션 방지 (파라미터화 쿼리)
- [ ] XSS 방지 (HTML 이스케이프)
- [ ] 인증·인가 검증
- [ ] 에러 메시지에 민감 정보 미포함
- [ ] 의존성 취약점 점검

## 비밀값 관리

- 소스 코드에 비밀값 절대 하드코딩 금지
- 환경변수 또는 시크릿 매니저 사용
- 시작 시 필수 환경변수 존재 여부 검증
- 노출된 비밀값은 즉시 교체

```bash
# 환경변수 검증 예시
if [ -z "${API_KEY}" ]; then
    echo "[ERROR] API_KEY 환경변수 필요" >&2
    exit 1
fi
```

## 시스템 레벨 보안

저수준 코드에서 추가 확인:

- **버퍼 오버플로** — 경계 검사 없는 메모리 쓰기 금지 (`strcpy` → `strncpy`)
- **포맷 스트링** — `printf(user_input)` 형태 금지 → `printf("%s", user_input)`
- **정수 오버플로** — 부호 있는 정수 연산 전 범위 검증
- **POSIX 권한** — 파일·소켓 권한 최소화 원칙 (`chmod 600`, `umask`)
- **setuid/setgid** — 사용 전 필요성 재검토, 사용 시 권한 즉시 드롭

## 보안 이슈 대응 절차

1. 즉시 작업 중단
2. `code-reviewer` 에이전트로 영향 범위 분석
3. CRITICAL 이슈 수정 후 계속 진행
4. 노출된 비밀값 즉시 교체
5. 유사 패턴 전체 코드베이스 점검
