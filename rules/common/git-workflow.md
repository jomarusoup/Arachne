# Git 워크플로

## 커밋 메시지 형식

```
<type>: <설명>

<선택적 본문>
```

### 타입

| 타입       | 의미                     |
| ---------- | ------------------------ |
| `feat`     | 신규 기능 추가           |
| `fix`      | 버그 수정                |
| `refactor` | 동작 변화 없는 코드 정리 |
| `docs`     | 문서 수정                |
| `test`     | 테스트 추가·수정         |
| `chore`    | 빌드·설정·의존성 변경    |
| `perf`     | 성능 개선                |
| `style`    | 포맷·코딩 스타일 수정    |

### 예시

```
feat: IPC 소켓 연결 타임아웃 추가

epoll 이벤트 루프에 연결 타임아웃(30s)을 추가.
클라이언트 응답 없을 때 좀비 연결 방지.
```

```
fix: fork() 후 좀비 프로세스 누수 수정

waitpid(WNOHANG)를 SIGCHLD 핸들러에 추가해
자식 프로세스 종료 시 즉시 회수하도록 수정.
```

## 브랜치 전략

- `main` — 항상 빌드·테스트 통과 상태 유지
- `feat/<기능명>` — 신규 기능 개발
- `fix/<버그명>` — 버그 수정
- `refactor/<대상>` — 리팩터링

## PR 워크플로

PR 생성 시:

1. 전체 커밋 이력 분석 (`git diff [base]...HEAD`)
2. 변경 범위 요약 작성
3. 테스트 플랜 체크리스트 포함
4. 새 브랜치면 `-u` 플래그로 푸시

## 커밋 전 자동 실행 (수정 완료 시)

```
/verify → git add → git commit → git push
```

별도 요청 없이 이 순서로 자동 진행.
