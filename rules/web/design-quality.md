# 웹 디자인 품질 기준

> [common/patterns.md](../common/patterns.md)를 웹 디자인 품질 관점으로 확장한다.
> 레이아웃 **수치·메커니즘**(열 폭·패딩·버튼 크기)은 [common/ui-layout.md](../common/ui-layout.md)에서,
> 이 파일은 그 위의 **의도·미감 레이어**(무엇을 만들지, 왜 그렇게 보이게 할지)를 다룬다.
> 여기 원칙(위계·리듬·깊이·인터랙션 상태)은 웹 클라이언트를 **독립 데스크톱 프로그램**으로
> 전환해도 그대로 이식된다 — UI 감각은 프레임워크에 종속되지 않는다.

## 안티-템플릿 정책

제네릭한 템플릿처럼 보이는 UI를 출하하지 않는다. 프론트엔드 결과물은 의도적이고,
주관이 있으며, 제품에 특화돼 보여야 한다.

### 금지 패턴

- 균일한 간격에 위계가 없는 기본 카드 그리드
- 가운데 정렬 헤드라인 + 그라데이션 blob + 제네릭 CTA의 흔한 히어로 섹션
- 라이브러리 기본값을 손대지 않고 완성된 디자인인 척
- 레이어링·깊이·모션이 없는 납작한 레이아웃
- 모든 컴포넌트에 동일한 radius·간격·그림자
- 회색-온-화이트에 장식용 강조색 하나만 얹은 안전한 스타일
- 사이드바 + 카드 + 차트의 관점 없는 "숫자 채우기식" 대시보드
- 의도 없이 쓴 기본 폰트 스택

### 필수 품질

의미 있는 모든 프론트엔드 표면은 아래 중 **최소 4개**를 보여야 한다:

1. 스케일 대비를 통한 명확한 위계
2. 균일한 패딩이 아닌 의도적인 간격 리듬
3. 오버랩·그림자·서피스·모션을 통한 깊이/레이어링
4. 캐릭터가 있는 타이포그래피와 실제 페어링 전략
5. 장식이 아닌 의미론적으로 사용된 색
6. 디자인된 느낌의 hover·focus·active 상태
7. 적절한 곳에서 그리드를 깨는 editorial/bento 구성
8. 비주얼 방향에 맞을 때의 텍스처·그레인·분위기
9. 산만하게 하지 않고 흐름을 명확히 하는 모션
10. 부가물이 아닌 디자인 시스템의 일부로 다뤄진 데이터 시각화

## 프론트엔드 코드 작성 전

1. 구체적인 스타일 방향을 정한다. "깔끔한 미니멀" 같은 모호한 기본값을 피한다.
2. 팔레트를 의도적으로 정의한다.
3. 타이포그래피를 신중히 선택한다.
4. 최소한 소수의 실제 레퍼런스를 모은다.
5. 관련 디자인/프론트엔드 스킬(`make-interfaces-feel-better`, `frontend-patterns`)을 활용한다.

## 검토할 만한 스타일 방향

- Editorial / 매거진
- 네오-브루탈리즘
- 실제 깊이가 있는 글래스모피즘
- 절제된 대비의 다크/라이트 럭셔리
- Bento 레이아웃
- 스크롤리텔링
- 3D 통합
- 스위스 / 인터내셔널
- 레트로-퓨처리즘

다크 모드를 자동 기본값으로 삼지 않는다. 제품이 실제로 원하는 비주얼 방향을 고른다.
