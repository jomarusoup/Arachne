# 시스템 프로그래밍 결정 레지스터 (2026-10-05 확정)

> 근거와 대안은 [ADR-0005](../../docs/decisions/0005-programming-philosophy.md)에 있다.
> 이 표가 [philosophy.md](philosophy.md) 본문보다 우선한다. 바꿀 때는 ADR-0005를 supersede한다.

| 결정 | 선택 | 이유 |
|---|---|---|
| D01 기존 관례 | 혼합: 스타일은 기존 관례, 안전성·에러·동시성은 철학 | 기존 Pro*C·C 자산 |
| D02 포매팅 | 저장소 `.clang-format`, 없으면 LLVM | 도구에 맡긴다 |
| D03 C++ 에러 | 경로 분리: 핫패스 `noexcept` + 에러 값 | 핫패스 예외 비용 |
| D04 Rust 에러 | 라이브러리 `thiserror`, 앱 최상위 `anyhow` | 생태계 관용 |
| D05 불변식 위반 | 개발 빌드 즉시 중단, 운영은 해당 요청만 실패 | 서비스 유지 |
| D06 최적화 | 경로 기반: `HOTPATH` 주석 경로만 설계부터 | 측정 우선 + 저지연 |
| D07 자료구조 | 표준 컨테이너 우선, C는 `c-data-structures` | 연속 메모리 |
| D08 이식성 | 서버는 리눅스 전용 허용(한 모듈 격리) | epoll·io_uring |
| D09 데이터 형식 | 설정·로그 텍스트, 핫패스 프로토콜 바이너리 | 경계별 비용 |
| D10 내부 API | 외부만 호환 유지, 내부는 호출자와 함께 변경 | 커널 방식 |
| D11 Rust `unsafe` | 격리 허용 + `// SAFETY:` 필수 | 최소 범위 |
| D12 동시성 | 메시지 패싱 우선 + 락 기반 공유 상태 허용 | 공유메모리-DB 계층 |
| D13 Rust 비동기 | 주변부 Tokio, 핫패스 전용 스레드 | 지연 예측성 |
| D14 매크로 | C 함수형 매크로 금지, 로그·X-매크로만 예외 | C에 대체 수단 없음 |
| D15 테스트 시점 | 기능과 같은 변경, 버그는 재현 테스트 먼저 | 회귀 방지 |
| D16 언어 표준 | C11 / C++20 / Rust 2024 | 가정(R8) |
| D17 언어 | 주석·커밋 전부 한국어 | 하네스 규약 |
| D18 불변성 | 언어별 분리: 시스템 언어는 소유자 하나·범위 명확 | 제자리 갱신 정상 |
| D19 네이밍 | C/C++ 하우스 스타일, Rust 관용, `_t` 폐지 | POSIX 예약 |
| D20 헤더 | 날짜 필드 삭제, 함수 헤더는 공개·비자명만 | git이 정본 |
| D21 커버리지 | 80%는 신규 모듈만, 레거시는 변경 라인 | 비용 대비 효과 |
| D22 지연 스킬 | 웹 지연과 프로세스 내부 핫패스 분리 | 역할 경계 |
| D23 배치 | `rules/systems/` 신설, paths 지연 로드 | 웹 작업 비용 0 |

D12 공유 상태 조건(락 순서 문서화·robust 뮤텍스 복구)은 [philosophy.md](philosophy.md) 11절에 있다.
